Permission overwrite order: everyone, aggregate role denies/allows, member denies/allows.
Owner and ADMINISTRATOR bypass channel overwrites. VIEW_CHANNEL and SEND_MESSAGES
have implicit restrictions. Threads inherit parent channel permissions and use
SEND_MESSAGES_IN_THREADS; unconfirmed private-thread membership is denied. Timeout
retains view/history while preventing sending/new reactions.

The permission object is shared by navigation, the composer, member/search scope,
reaction actions and forwarding destinations. Every mutation is checked again in
Controller. Reactions already present do not require ADD_REACTIONS, but creating a
new bucket does. Existing counts remain visible regardless of that permission.
Gateway events update reaction counts/current-user state and channel ACL changes
invalidate old member scope. Partial channel updates merge previous ACL fields.

Deliberate limits:
- Member subscription is for the current visible channel, starting at 100 entries
  and extended only by an explicit More action up to 2000 retained list entries.
- Membership is not fetched by indiscriminate guild REST enumeration.
- List packets are accepted only with a matching server member_list_id, a confirmed
  everyone list, or an explicit matching channel_id. If a private list only exposes
  an unverified hash, it is left unavailable rather than mixing another channel's
  members. This coverage limitation must be disclosed, not called full parity.
- Server search people are current scoped members plus authors of current-channel
  messages and self; private/group scope is current recipients only. Numeric filter
  identifiers outside that scope are rejected before REST.
- Forwarding accepts up to 10 destinations, retains bounded destination metadata
  across guild switches, and re-fetches effective destination permissions before
  any POST. Failure after a partial send is reported without automatic replay.
- Prepared files are not sent on selection. Explicit confirmation can submit up
  to 10 files, each <=25 MiB and total<=100 MiB; nonce uses24 hex characters while
  draft acknowledgements retain the full32-character submission id.
